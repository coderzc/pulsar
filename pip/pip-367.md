# PIP-367: Add beforeMessageReceive api for ConsumerInterceptor

# Background knowledge

ConsumerInterceptors is a plugin interface that allows you to intercept (and possibly mutate) messages received by the consumer.

https://pulsar.apache.org/docs/client-libraries-consumers/#intercept-messages

# Motivation

In such cases, users want to know whether the message has been delivered to the consumer on the client side. Sometimes, the message is actually delivered to the consumer but, due to other reasons, it remains in the internal queue and is not returned to the consumer caller.

Therefore, I wants to add an api on the ConsumerInterceptor to intercept all messages delivered to the client.

# Goals

## In Scope

- Support beforeMessageReceive api for ConsumerInterceptor.

# Detailed Design

## Design & Implementation Details

Add beforeMessageReceive api for ConsumerInterceptor.

```java
public interface ConsumerInterceptor<T> {
    /**
     * This interface is invoked when a message has just reached the client through the socket interface.
     *
     * @param consumer the consumer which contains the interceptor
     * @param message the message to be consumed by the client.
     * @return message that is either modified by the interceptor or same message
     *         passed into the method.
     */
    default Message<T> beforeMessageReceive(Consumer<T> consumer, Message<T> message) {
        return message;
    }
}
```

# Backward & Forward Compatibility

Fully compatible.
